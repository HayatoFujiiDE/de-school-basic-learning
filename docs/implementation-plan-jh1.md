# 中学1年数学の実装契約

## 1. 目的
中1数学38単元を追加し、各8問、ゲーム1問、説明確認、解説例、誤解の説明、2種類以上の関心別入口、操作できる図を提供する。段階アニメーション8本とローカル解説動画2本を加える。全画面を3幅・2表示で検証し、数学・保存・描画を制作担当とは別の担当で確認する。

## 2. 範囲
追加教材、図、動画、公式コード抽出、受理・表示・保存の学年対応、検査と引継ぎ資料。外部AI、個人情報入力、会員管理、課金、新しい式評価器は含めない。小学4～6年の原稿はbyte単位で保持する。

## 3. 開始時点
main e0f74ee、版4、66単元・513練習問題。独立repo、file://、ES2017、通常script、Google Fonts以外の外部実行依存なし。公式83V11の中1数学は107行。学年コードは835021であり、825027ではない。

## 4. 依存関係
公式Excel/PDF → 単元map → 原稿/操作図設計 → 独立数学レビュー → evidence更新 → 全件registry → UI/保存統合 → 全検査 → 公開差分監査 → commit/PR。原稿と図は凍結map・state/claims契約で並行。レビュー担当は作者の解答ledgerを独立期待値の生成元にしない。

## 5. 影響面
core（code、course、受理、sort、保存）、app（routeと学年/教科/領域の表示）、index/catalogue、lesson許可集合、追加教材/図/scene/review/素材、旧版を孤立して検証するfixture、全件browser検査。旧素材の削除・主キー変更・保存key変更はしない。

## 6. 採用案
固定course metadataをcoreの一箇所へ置く。codeGradeは825024/5/6→4/5/6、835021→内部7を完全prefixで判定。core.gradeLabel、core.subject、core.domainsで表示を統一する。内部7は中学1年であり公式学年1と区別する。38の公式primary codeを用い、広い公式項目はcoverageで共同対応。原稿はunits-jh1.js、操作図とsceneは独立fileへ追加。表現式・π・分数は選択か並べ替えで採点し、数値入力は有限小数だけを完全一致で読む。数学用負号−の正規化のみ追加する。

## 7. 比較した案
A:各画面にgrade===7の分岐を加える最小差分。学年/教科/領域/保存判定が散り、検査の抜けを招くため不採用。B:固定course metadataと独立教材fileを採用。C:式パーサと外部数学rendererを導入する案は、オフライン契約と採点範囲を不必要に広げるため不採用。

## 8. リスク・失敗行列

## 9. 検証
独立107行照合・69終端対応、全304問と38ゲームの独立期待解、全文とclaims照合、旧66のbytes/組立結果保持。v4 fixtureで旧回帰を継続し、v5全104集合を別検査。全操作域・各scene101phase、可視部品と数の対応・軸尺度・ID一意性。全route×1440/1024/390×2mode、全問採点、説明確認、保存/reload、動画停止、横はみ出し/禁止語/JS/network検査。指摘修正後に全件再検査し、変更がなければ無意味な再実行はしない。

## 10. 復旧
版5互換coreと104教材の保存対象を維持し、中1入口のみ停止する。旧版coreへ単純巻戻ししない。保存削除や旧66原稿変更を復旧策に使わない。実装は独立branch/worktree、merge前のmain再fetchと差分確認を行う。

## 11. 未決事項
次の拡張順、達成率文言、サポーター指標、追加ゲームはQUESTIONS.mdへ。今回の既定は既存契約を継続。公式Excel row662の『柱体や体』は原本のまま保存し、PDF印刷p78の『錐体』に従って教材を制作する。原本差異は資料に注記する。

## 12. 承認
実装・検証・push/mergeは会話内で承認済み。外部サービスの導入や権限変更は行わない。教材の運営による配信承認を捏造せず、publication=preview、humanApproval=nullを維持する。
