# ファクトリーとの受け渡し

`js/units.js`（4年）、その後に読み込む `js/units-grade5.js`（5年）、`js/units-grade6.js`（6年）、`js/units-jh1.js`（中1）が `window.BL.data` を構成する静的な教材素材です。`file://` で読み込むため、JSONを取得する通信やモジュール読み込みは使いません。ファクトリー側は同じスキーマでJSを生成し、検証後にファイルを差し替えます。

各単元の主キーは文部科学省の学習指導要領コード（16文字の文字列）です。`coverageCodes` は扱う他の公式コードへの対応です。第4学年には `8250245A00000000` のように英字を含むコードもあるため数値へ変換しません。単元名・順番は編集できますが、コードを独自の連番に置き換えません。

`claims` に主張ID・本文・確かさ・出典IDを置きます。説明、関心別の例、問い、解答とその理由、バディの見本はこの主張の範囲に収めます。`adapt-rules` は変えてよい言い回し等と、変えてはいけない数・単位・定義・条件を区別します。練習・ゲーム・バディは `claimIds` で根拠と結びます。カタログとのつながりは `entries[].category` と `activityIds` です。

静的な出力前検査は、検証済み主張、根拠ID、文言、数値、選択肢、並べ替えの集合、単元コード、確認状態を点検します。`review.evidence !== 'verified'` の素材や壊れた素材は `BL.core.units()` に出ません。これは記述された確認状態と構造を点検する仕組みであり、自由文の真偽や個人名を自動的に証明する機能ではありません。独立した検証担当による内容の確認を別に必須とします。

この版は `review.publication: 'preview'` の制作プレビュー専用です。`humanApproval: null` は運営の公開承認が未実施という意味です。子ども向けの配信APIはありません。公開時には実際の承認記録を持つ配信側で「利用できる」版だけを選ぶ仕組みを別途用意します。承認値を書き換えただけで配信を始めません。

今回の実行環境は外部AIに接続せず、確認済みの固定文と選択操作だけで動きます。その場生成を加える場合は、必ずclaimsとadapt-rulesを渡し、禁止語・個人名・根拠外の事実を出力前に検査します。不合格時に使う承認済み変奏、個人を含まない事後確認の記録、有限リトライ・課金上限を配信前に実装します。現在の静的ガードをLLMの意味検証の代わりとはしません。

学習状態は `des.basic-learning.v1` だけに保存します。教材内容を変更するときは `BL.data.version` を必ず更新します。原則として版が異なる過去の正誤・自己確認は引き継がず、表示モードと関心を維持します。現行版5への例外移行は、元ファイルと組立後の既存教材の完全同一性を独立検査したうえで、版2から4年、版3から4・5年、版4から4・5・6年の記録を移します。以前の版2→3、版2/3→4の互換検査も残します。対象外の学年・未知版はこの例外で移しません。学年表示の絞り込みと保存対象は分け、常に全学年の記録を保ちます。誤りを修正した素材に、旧版の説明確認が残ることを防ぎます。原文の自由入力は保存対象に含みません。

差し替え手順:

1. 公式コードとの対応、全claims、全変奏、全解答を制作担当とは別の担当で検証する。
2. 未確認のものはpendingのまま残す。検証が終わった素材だけevidenceをverifiedへ更新する。
3. `BL.data.version` を更新し、`sh tools/check.sh` を実行する。既存ファイルはコミットで復元できる状態にする。
4. 制作プレビューで運営が内容を見る。公開承認と配信への適用は別途実施する。

5年の追加素材は既存codeを上書きせず、各unit.grade=5と公式codeの学年が一致する必要があります。`core.units()`は全学年、`core.units(grade)`は画面表示用の選択結果です。追加script未読込のまま検査が通らないよう、独立した期待code集合と組立後の結果を完全一致させます。

## 6年追加時の保存版4の契約（維持する回帰範囲）

4・5年の44単元の元ファイルと組立後の内容を変えず6年22単元を追加する。例外移行を2→4（4年のみ）、3→4（4・5年のみ）へ広げる。版2の5・6年、版3の6年の記録や再開先は引き継がない。全学年を保存対象とし、学年ボタンだけで記録を削除しない。

`js/catalogue.js` は原稿とは独立した66コードの期待集合と版4を宣言する。HTMLにも期待版を持ち、追加scriptやregistryの欠落、同数の別code置換、重複、学年矛盾を検出する。欠落時は `core.ready=false` でファイル確認の案内のみを出す。raw集合が完全でもpending等で受理されない単元がある場合は、確認済み教材の閲覧だけを許し、保存を止める。

`core.readOnly` は学習stateの外で保持し、sanitizeで版を変えても解除しない。保存の外側の構造（object、認識済みversion、objectのprogress）が壊れている場合、未知の版、読取拒否、教材不完全の場合はsave/reset/removeItemを止め、元の文字列を保つ。認識済みrecord内の回答値・自己確認は既存の厳密な正規化と再採点を行う。保存だけが拒否される場合もメモリ内で続けられるが、画面に今回の回答が保存されないことを示す。

ロールバックで旧版3のcoreへ単純に戻さない。版4互換のcore・66教材と保存対象を保持し、必要なら6年の入口だけを非表示にする。既存の保存を削除して復旧したことにしない。

## 中1追加・保存版5

公式code `835021` は中学校数学第1学年を示す。内部の `unit.grade=7` は表示・保存の識別用で、公式学年1とは別である。`codeGrade`は学校段階を含む完全prefixで判定する。`core.gradeLabel/subject/domains`は中1を「中学1年生」「数学」「数と式・図形・関数・データの活用」へ対応させる。小学生／中学生向け表示の選択とは独立している。

原稿38単元を追加し、期待catalogueは版5・104code。`sources/catalogue-v4.json`は旧版66codeの孤立回帰用fixtureであり、配信catalogueではない。版2/3/4の保存に含まれる中1進捗・再開先・選択学年は引き継がない。未知版・破損・読取失敗の保存停止は旧契約を維持する。復旧は版5のcoreと104教材を保持して中1入口だけを停止する。

数値入力では数学の負号「−」とASCII/全角の負号を正規化する。整数・有限小数を厳密に読み、式・指数表記・分数文字列・Infinity等を評価しない。π、分数、文字式そのものを回答する場合は選択か並べ替えを使う。中1の数値入力は負号が入力できる通常キーボードを指定する。
