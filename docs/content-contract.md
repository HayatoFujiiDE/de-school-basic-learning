# ファクトリーとの受け渡し

`js/units.js`（4年）と、その後に読み込む `js/units-grade5.js`（5年）が `window.BL.data` を構成する静的な教材素材です。`file://` で読み込むため、JSONを取得する通信やモジュール読み込みは使いません。ファクトリー側は同じスキーマでJSを生成し、検証後にファイルを差し替えます。

各単元の主キーは文部科学省の学習指導要領コード（16文字の文字列）です。`coverageCodes` は扱う他の公式コードへの対応です。第4学年には `8250245A00000000` のように英字を含むコードもあるため数値へ変換しません。単元名・順番は編集できますが、コードを独自の連番に置き換えません。

`claims` に主張ID・本文・確かさ・出典IDを置きます。説明、関心別の例、問い、解答とその理由、バディの見本はこの主張の範囲に収めます。`adapt-rules` は変えてよい言い回し等と、変えてはいけない数・単位・定義・条件を区別します。練習・ゲーム・バディは `claimIds` で根拠と結びます。カタログとのつながりは `entries[].category` と `activityIds` です。

静的な出力前検査は、検証済み主張、根拠ID、文言、数値、選択肢、並べ替えの集合、単元コード、確認状態を点検します。`review.evidence !== 'verified'` の素材や壊れた素材は `BL.core.units()` に出ません。これは記述された確認状態と構造を点検する仕組みであり、自由文の真偽や個人名を自動的に証明する機能ではありません。独立した検証担当による内容の確認を別に必須とします。

この版は `review.publication: 'preview'` の制作プレビュー専用です。`humanApproval: null` は運営の公開承認が未実施という意味です。子ども向けの配信APIはありません。公開時には実際の承認記録を持つ配信側で「利用できる」版だけを選ぶ仕組みを別途用意します。承認値を書き換えただけで配信を始めません。

今回の実行環境は外部AIに接続せず、確認済みの固定文と選択操作だけで動きます。その場生成を加える場合は、必ずclaimsとadapt-rulesを渡し、禁止語・個人名・根拠外の事実を出力前に検査します。不合格時に使う承認済み変奏、個人を含まない事後確認の記録、有限リトライ・課金上限を配信前に実装します。現在の静的ガードをLLMの意味検証の代わりとはしません。

学習状態は `des.basic-learning.v1` だけに保存します。教材内容を変更するときは `BL.data.version` を必ず更新します。原則として版が異なる過去の正誤・自己確認は引き継がず、表示モードと関心を維持します。版2→3のみ例外で、元ファイルと組立後の4年全教材の完全同一性を独立検査したうえで4年の回答・自己確認・再開先を移行します。5年や他版はこの例外で移しません。学年表示の絞り込みと保存対象は分け、常に全学年の記録を保ちます。誤りを修正した素材に、旧版の説明確認が残ることを防ぎます。原文の自由入力は保存対象に含みません。

差し替え手順:

1. 公式コードとの対応、全claims、全変奏、全解答を制作担当とは別の担当で検証する。
2. 未確認のものはpendingのまま残す。検証が終わった素材だけevidenceをverifiedへ更新する。
3. `BL.data.version` を更新し、`sh tools/check.sh` を実行する。既存ファイルはコミットで復元できる状態にする。
4. 制作プレビューで運営が内容を見る。公開承認と配信への適用は別途実施する。

5年の追加素材は既存codeを上書きせず、各unit.grade=5と公式codeの学年が一致する必要があります。`core.units()`は全学年、`core.units(grade)`は画面表示用の選択結果です。追加script未読込のまま検査が通らないよう、独立した期待code集合と組立後の結果を完全一致させます。
