## 構成・境界・復旧

追加方式Bを採用する。既存definitionsへ完全一致コードで登録し、重複を登録前に拒否する。scene rendererは自分の6コードだけ処理し、それ以外は元のrendererへ渡す。二重読込を無作用にする。共通state/bind/player/保存処理は変更しない。CSSはgrade6専用の親selector内に限定する。HTML文字はescapeし、SVGは現playerの許可要素・属性だけを使う。検査用の識別は固定id。

stateの数値は整数。分数の分子・分母を整数で保持し、浮動小数stepを使わない。各fieldの任意の組合せでも分母0・負の個数・描画領域外にならない範囲にする。算式・図・ラベル・altは同じstateから作る。代表値は架空の数値だけを使う。

破壊しうる境界は、旧codeの上書き、renderer fallback欠落、CSS漏出、異なる単位の縮尺混同、途中の部品遮蔽、誤ったtryIt状態。旧44定義/14sceneの出力hash比較、未知code/二重読込対照、全状態・全phaseの独立数量検査、実Chromeの文字bbox・操作・cleanupで検出する。復旧は追加4ファイルとroot所有の読込/許可コード差分を対象に戻す。既存教材や学習記録はこの変更で削除・変換しない。

## 6つの4段階解説とmotion claim案

### 8250263112100000 分数乗法（root動画と同じ）
1. 同じ全体1を縦3、横4に分けた12区画。2/3を示す。
2. その2/3のうち3/4を取る。交わる領域は2列×3行。
3. 交わる6区画を読む。区画の面積1/12と全体1の大きさを固定する。
4. 6/12=1/2。`tryIt={n:3}`。

面積の二つの指定領域は意図した重なりで、物体の重複遮蔽とは区別する。12区画を消したり丸めたりせず、色/境界線で選ぶ範囲を変える。

### 8250263110000000 分数除法
1. 全体1を12等分。3/4は9区画、2/3は8区画。
2. 9区画の中から8区画で1つ分を囲む。残りは1区画。
3. 除数8区画を新しい1つ分と見る。残り1区画は、その1/8。
4. 9÷8=9/8=1と1/8。3/4÷2/3=3/4×3/2を対応させる。`tryIt={divisor:'8'}`。

同一幅の区画9個を全段階で追える。元の1/12と除数の1/8はラベル領域を分ける。量を運ばず、境界線と括りを描く。

### 8250263211200000 線対称
1. 垂直な対称軸と三角形ABCを見る。Aは軸から3cm、BとCは1cm。
2. Aから軸へ垂直に進み、反対側にも3cmの位置に対応点を取る。
3. BとCも軸から同じ距離に取る。対応点を結ぶ線分は軸と垂直、軸が中点を通る。
4. 対応点を結ぶと合同な三角形。`tryIt={axis:'vertical',point:'A'}`。

元の三角形を潰して裏返す補間はしない。固定位置に対応点を順に作図し、垂線のガイドを伸ばす。元図と新しい作図を明示する。

### 8250263320000000 比の利用（root動画と同じ）
1. 全体20個を確認する。
2. 比2:3は全部で5まとまり。1まとまり20÷5=4個。
3. 2まとまりをA、3まとまりをBに対応させる。
4. Aは8個、Bは12個、合計20個。`tryIt={a:2,total:20}`。

初めから5列×4個を置き、区切りと色の対応を変える。全20部品を常に見せ、直線再配置による交差を作らない。

### 8250263230000000 円の面積
1. 半径3cmの円を確認する。
2. 正確な円弧を保った16個の等面積扇形に分ける。
3. 同じ16片を交互に並べた形を見る。曲線が残るため「長方形に近い形」と説明する。
4. 細かく分けると、横が円周の半分・縦が半径に近づく。円周率3.14として3×3×3.14=28.26cm²。`tryIt={r:3,sectors:'16'}`。

円を多角形に置き換えて面積を減らさない。分割片は固定ID・一定半径/角度。組替えの場面では完成配置へ段階切替し、切断線・曲線側の寸法ガイドを動かす。未検証の飛行経路で16片を交差させない。有限分割の実幅を9.42cm、高さを厳密な3cmと偽らず、極限として近づく説明と分ける。連続的な片の移動を追加する場合は、別途全phase非交差・領域包含が成立する経路を先に確定する。

### 8250263311300000 反比例
1. 横3cm、縦4cm、面積12cm²の長方形。
2. 横を2倍の6cmにすると、縦は1/2の2cm。
3. 横を1/3の2cmにすると、縦は3倍の6cm。
4. どれも横×縦=12。`tryIt={x:'3'}`。

動く間は横x(t)に対して縦12/x(t)をその都度計算し、面積を保存する。長さは連続量として扱い、途中に整数個の1cm²ブロックを捏造せず、丸めた整数の寸法を表示しない。

## 描画IDと可視性の検査

全操作図の結論HTMLは`visual-output-summary`、全sceneの結論textは`output-summary`。同じunitで両方表示してもDOM IDを重複させない。sceneの数量IDは乗法`mul-cell-x-y`、除法`div-part-i`/`div-unit-i`、線対称`sym-source`/`sym-target`と各対応点、比`ratio-dot-col-row`、円`circle-piece-i`、反比例`inverse-material`。数量図形のID・座標・面積と、文字/色境界の可視性を別々に検査する。

乗法の濃色セルは白い境界線で分け、6区画を数えられるようにする。初稿の塗りと同色の境界は制作時の実Chrome目視で検出した。12矩形・濃色6の数量は不変のまま、境界コントラストを1から5.513へ改善。root独立gateにコントラスト3以上と旧同色を拒否する陽性対照があり、実行して合格を確認した。

点対称の操作図は三角形1枚が点対称だとは扱わず、元の輪郭と180°回した像の対応を見る。度数と統計探究の補足実値は15px以上で表示する。

## 検証契約

制作前に図/文字/数式の領域を固定する。整数部品はID集合・総数・色分け数を確認し、幾何量は同じ縮尺で面積・辺・距離・角度を検査する。全state組合せを有限列挙し、全scene各stepのphase0..1を101点以上で検査する。端点合格だけで完了扱いにしない。

実Chromeで文字bboxの領域包含・文字同士/数量部品との交差を確認し、390幅でも同じ単位の目盛を読める大きさにする。旧44図/14scene出力不変、二重読込、既知/未知state、pending非表示、全22実教材の390両mode、キーボード、全段階・tryIt・進捗不変を確認する。誤った分割、部品欠落、元の交差経路、分母0、旧renderer未委譲をそれぞれ陽性対照にする。
